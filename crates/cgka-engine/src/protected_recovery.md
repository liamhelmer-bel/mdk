# Dormant recovery journal and consumer-anchor foundation

Approved design: H f5c24abf9a3def22937c90f98fecd1869c09e415, genuine Marmot decision 4jf4. This source slice implements filesystem mechanics, not a public trusted factory, a production receiver or the whole approved recovery protocol.

The private owned-descriptor boundary holds actual exclusive kernel locks on journal, account storage lease and separately supplied consumer anchor. It checks regular/private/non-hardlinked distinct file descriptors; supplied directory handles are synced after header creation. Enrollment sorts unique operators and mints a fresh native random generation. Both journal and consumer anchor append, fsync and hash-chain every checkpoint; one-use keys bind original header, actual card completion sequence, ask and operation digest. A use is refused if its original card does not match or the consumer anchor already retains it. The anchor is scanned with bounded record allocations rather than an unbounded in-memory replay map.

Strict clean reopen verifies canonical finite records, global ordering, both chains, exact anchored prefix, original enrollment, clock monotonicity and one-use retention. It supports matched clean file checkpoints. Deletion, valid-prefix restore with an ahead anchor, unmatched suffix, partial line, unknown/duplicate fields, competing ownership or changed enrollment refuses without rewriting existing records. Append failure latches; no blind retry. Completed history has no lifetime count or byte limit.

## Explicit remaining contracts

Protected installation must actually create these files with O_EXCL, refuse path symlinks/ancestors, independently protect the consumer anchor outside receiver restore custody, and own their authenticated protected peer handoff. A distinct inode is not proof of independent trust or backup exclusion. This slice accepts only internal owned descriptors and exposes no public constructor or import authority; it cannot qualify missing deployment custody through a boolean.

The private native receiver now supports a fresh-only ordered sink. Its actual Engine account, group, canonical operators and exact epoch/indexed credentials/extensions projection must match the original owned header; nonempty historical journals refuse this constructor. Actual source wire/outcome and semantic publication/decision/consumption records are globally ordered and anchored. The existing real semantic publication owner supplies CardComplete only after all actual adapter publish reports meet its finite positive endpoint-ack contract. This means positive publish acknowledgments, not proof that a human saw the card. Actual consume derives the original retained operation SHA and binds its independent one-use anchor to the original header and exact CardComplete sequence. The source test uses real signed Nostr/MLS publication mechanics and authenticated reaction ingestion with a synthetic relay acknowledgment fixture; production endpoint/custody qualification remains absent.

Every actual native MessageReceived outcome retains its immutable group/content ID/sender/source epoch/payload SHA before native plaintext acknowledgment, including nonoperators that yield no approval candidate. Positive pending reconciliation streams closed wire/outcome records and checks each actual current native pending tuple matches exactly once, rejects incomplete wire/outcome pairs and unknown Welcome/lifecycle pending events before any deletion, and never replays a wire. Application metadata omitted from the immutable projection is intentionally irrelevant. This narrowly scoped reconciliation method does not construct a recovered semantic factory or issue authority from a deserialized receipt.

Opaque semantic transition payloads remain chained, not yet a complete closed semantic recovery validator. The exact semantic reconstruction/expiry validator, current-native readback against latest directly captured update, original join provenance capture, compact terminal index and operational protected factory remain separate source integration slices. Direct-native update capture itself is implemented in the preceding source slice, but that does not implement the restart policy validator. Until then this foundation cannot open the production approval path. A journal suffix ahead of the anchor stays HOLD rather than claiming it proves local completion.

Advisory locks require stable protected inode custody and positively stopped old owner. Arbitrary privileged modification or joint restoration of anchor and receiver is outside clean restart; ordinary files cannot detect it. Real disk/fsync failure may leave a retained unmatched suffix; this slice does not reserve disk or resume external effects. Linear incremental lookup is bounded in memory but not claimed as production throughput qualification. No legacy UNKNOWN is settled or replayed.

Actual filesystem fixtures cover restart and consumer one-use; old-prefix restore against the independent fixture anchor; interior deletion/partial records/anchor mismatch; canonical unique operators; second opener and same-inode alias; generation/card/clock binding; a real write on a read-only anchor after journal fsync; real Linux procfs directory-fsync failure; and more than32MiB history followed by matched reopen/new card. These are source mechanism tests, not independent UID custody or native MLS semantic qualification.


The ordered sink's per-record bound is12MiB encoded, allowing at most4MiB original source JSON represented as hex plus envelope fields. This is a per-record allocation bound; there is no lifetime history cap or disk-space reservation. Original source bytes and canonical operation bytes stay distinct. `record_source` is private and receives actual owner records; accepting these fixed record schemas is not a public plaintext authority API. File descriptors supplied by tests and synthetic profile/welcome pins do not establish protected installation provenance.
