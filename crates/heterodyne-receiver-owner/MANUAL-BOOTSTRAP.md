# Manual receiver initialization and join

The separate fixed no-argument `heterodyne-receiver-manual-bootstrap` entry uses
exactly the root-owned initializer profile/parent/ledger/lifetime lease/expiry
inherited on FD3..7. It accepts an empty environment, effective root, and no
arguments. It does not require or consume a deployment packet, producer Git
proof, host-admission socket, or admission nonce. Such inputs confer no manual
join authority. The manual entry refuses any inherited FD 8, 9, 13, 14, 15 or 18.

It shares the existing bootstrap's installation verification, private finite
`/etc` mount, real owner-init/UID 899 child, actual publication and five original
storage descriptor transfer, root-owned namespace/UID 898 consumer peer, real
fresh MLS join and normal namespace cessation. Existing exclusive state records
and refusal to replay/adopt prior state are unchanged. Watch root-owned
`/var/lib/heterodyne/receiver-owner/<storage_generation>/01-initialized.json` for
the genuine published account, KeyPackage reference and event identity; an actual
pinned native invitation must target these exact observed values within the
fresh wait window. No member-count observation substitutes for join success.

After actual normal fresh-child exit and nonce/source-profile/frame checks,
`04-enrolled.json` retains the actual native enrollment, header and transport
group. The supervisor then retains all still-live bootstrap locals as well as all original directory/key/seed/database,
storage and root lifetime lease OFDs indefinitely. It starts no permanent
receiver and consumes no approval. Operator termination ends this custody; no
supported re-open/adoption/restart is inferred. A failure before this hold
retains exclusive issued/history state and needs reconciliation, never retry
by generating over the same state.

Deploy the separately pinned supervisor ELF outside the four-role indexed
release. This slice's common bootstrap source changes do not establish byte
equivalence of rebuilt indexed ELFs. Existing exact 174ac9d indexed binaries and
installation index remain the selected initializer/fresh roles; the new
supervisor selects and verifies those exact installed bytes. No automatic host
effect or new Product runtime entry is activated.

profile; FD4 actual UID 899/GID 899, mode 0700 generation parent; FD5 actual empty
UID 899/GID 899, mode 0600 read-write lifecycle ledger; FD6 actual root/root mode 0600
